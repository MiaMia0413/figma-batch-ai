# 自然语言与真实 Figma 验收清单

这份清单用于新编辑能力、目标匹配改动和发布前回归。自动化测试验证确定性逻辑，真实 Figma 验收负责发现 Plugin API、节点类型和视觉结果方面的问题。

## 自动化准入

运行：

```sh
npm run test:eval
npm run verify
```

验收标准：

- `tests/fixtures/edit-plan-cases.js` 至少同时覆盖中文、英文、选区、页面、模糊请求和未支持属性。
- 支持的确定性指令至少 95% 映射到预期工具和关键参数；主分支目标是 100%。
- 不支持和模糊指令不得误路由为已有修改工具。
- 模型生成的 target 不在用户上下文中时，工具必须在进入 Figma 主线程前被拒绝。
- 确认型工具必须经过 Preview，应用时只接受预览返回的 `nodeIds`。
- 用户取消后不得继续写入画布。

## 测试文件准备

建立一个不包含业务专有词的通用测试页，至少包含：

- 三组名称相同但层级不同的按钮或卡片。
- Frame、Group、Component 和 Instance 各一组，内部包含背景层、标题、正文和图标。
- 一个 Auto Layout 列表以及普通绝对定位列表。
- 使用纯色、变量绑定颜色、混合填充和无填充的图层。
- 使用普通字体、混合字体和本机不可用字体的文本图层。
- 锁定、隐藏以及不可编辑的节点各一个。
- 足够多的重复图层，用于验证页面级安全阈值和深度检索。

## 核心场景矩阵

| 场景           | 操作                      | 期望结果                               |
| -------------- | ------------------------- | -------------------------------------- |
| 页面级命名目标 | 修改所有主按钮背景色      | 只预览并修改按钮背景层，不修改文字颜色 |
| 选区容器       | 选中 Frame 后修改卡片圆角 | 向内找到正确背景层，范围不越过选区     |
| 容器内文本角色 | 修改登录弹窗标题文字      | 每个匹配容器只选择最可能的标题文本     |
| 文本子串替换   | 将旧 CTA 文案替换为新文案 | 保留文本节点中未匹配的其他内容         |
| 图层重命名     | 添加前缀或后缀            | 保留原名称，Preview 与 Apply 顺序一致  |
| 复制与布局     | 向右复制多个模块          | 副本不重叠，Auto Layout 内保持合理顺序 |
| 变量绑定填充   | 修改绑定颜色变量的图层    | 预览准确；应用结果明确，不静默扩大范围 |
| 字体缺失       | 修改不可用字体文本        | 确认面板提示字体问题，可选择备用字体   |
| 单节点失败     | 批次中包含锁定节点        | 其他节点继续执行，结果列出跳过项       |
| 深度检索       | 普通预览被截断后重新检索  | 保留 scope 和 target，只扩大扫描上限   |

## 安全与状态验证

每个修改工具至少验证一次：

1. Preview 自动选中目标，确认面板中的数量、名称和类型与画布一致。
2. 点击取消后画布没有属性写入，也没有新增空撤销步骤。
3. 点击应用后只修改 Preview 返回的节点。
4. Preview 后删除、移动到其他页面或改变目标类型，Apply 必须拒绝并要求重新预览。
5. 点击停止后不再发生选区变化和画布写入；若写入已完成，结果必须如实报告成功。
6. 每个实际写入的工具形成一个独立撤销点；只读和零修改结果不形成撤销点。
